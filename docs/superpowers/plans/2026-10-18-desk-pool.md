# Desk pool and members view (C3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline). TDD: each behaviour below is a test written and seen failing first.

**Goal:** Give the treasurer one page, `/desk/pool`, showing where the payout pool stands today (the whole-group payout view planned as S3d), an all-members table (sortable), and per-member share and net-return charts.

**Architecture:** One read hook returns every member's `payout_preview` row (admin only). A small pure module turns those rows and the member statistics from C1 into the pool lines and the sortable table rows. A page assembles them with the C1 charts. A Desk card links to it.

**Tech Stack:** as C1–C2 (React 19, TanStack Query, SVG charts from `src/features/charts`, Vitest).

**Spec:** `docs/superpowers/specs/2026-10-18-charts-and-group-reports-design.md` §5.

## Review Focus

- A non-admin makes no request and sees the admin-only screen. (Task 3.)
- The pool lines add up: savings + interest = what the records owe members; − owed + pots = the estimated payout, equal to the sum of the rows' `payout`. (Task 2.)
- Sorting every column, both directions, never reorders the totals row and never throws on ties or empty values. (Tasks 2–3.)
- No `NaN` in the table or charts for a member with no savings or no statements. (Tasks 2–3.)

### Task 2: Pool statistics (pure)

**Interfaces — Produces** in `poolStats.ts`:
```ts
poolLines(rows: PayoutRow[]): { savings: number; interest: number; entitled: number; owed: number; pots: number; estimated: number }
// savings = Σ savings; interest = Σ interest_earned; entitled = savings + interest (what the records owe members today);
// owed = Σ owed; pots = Σ pot_share; estimated = Σ payout. All sums in whole ngwee. Empty → all 0.

type PoolRow = MemberStat & { payout: number | null; defaulted: boolean };
memberRows(members: MemberStat[], payout: PayoutRow[], defaulted: Set<string>): PoolRow[]   // payout matched by member id, null when absent
type SortKey = 'name' | 'savings' | 'share' | 'loans' | 'interestCharged' | 'earned' | 'net' | 'roi' | 'due' | 'payout';
sortRows(rows: PoolRow[], key: SortKey, dir: 'asc' | 'desc'): PoolRow[]   // stable; names compare with localeCompare; null payout sorts last either way
```
Tests: lines on three rows (savings 1000/2000/400, interest 10/20/6, owed 0/0/200, pots 12.5 ×3, payouts 1022.5/2032.5/218.5 → savings 3400, interest 36, entitled 3436, owed 200, pots 37.5, estimated 3273.5 = entitled − owed + pots); empty rows → zeros; ngwee exactness (0.1 + 0.2); `memberRows` attaches payout and the defaulted flag, null payout for a member missing from the preview; `sortRows` ascending/descending for a number key and for names, ties keep their order, null payout last in both directions, input not mutated.
- [ ] Failing tests → implement → pass → commit `feat: pool statistics for the treasurer`.

### Task 3: The pool page

**Behaviour** (hooks mocked as in the Desk tests): non-admin → admin-only screen, no hook called; loading (labelled); error with retry; no closed month and no members → empty state "Nothing to show yet".
- **Payout pool today** section: lines "Members’ savings", "+ Interest collected so far", "= What the records owe members today", "− Owed back to the pool", "+ Fee and meeting pots shared equally", "= Estimated payout pool"; a note naming the month the figures use ("Worked from {open month} so far" / "from {last closed month}") and that it is an estimate until the cycle is paid out.
- **All members** table: columns Member (link to `/desk/members/:id`, with a "Defaulted" badge), Savings, Pool share, Loans taken, Interest charged, Interest earned, Net gain, Net return, Owed, Payout today; column headers are buttons with `aria-sort`, first press sorts descending (names ascending), second reverses; default sort savings descending; totals row (savings, loans, interest charged, interest earned, net, owed, payout) that never moves; a negative net or return is shown with its sign.
- **Share of the pool** (`DonutChart`: the picked member vs the rest, centre "{share} of all savings") and **Net return, all members** (`RankedBars` by `roi` as percent, the picked member highlighted) for a member chosen in a `SelectField` (default: the largest saver).
- A link "Download the whole-period workbook" to `/desk/reports`.
- Data: `useLedgerCycle`, `useCycleStatements(ids, true)`, `useGroupPayout(cycleId, true)`, `useMemberStatuses`, `useGroupMembers` (active members); `memberStats` from C1.

**Tests:** admin gate; the six pool lines with the worked numbers; the table rows and totals; sorting by a column and reversing, `aria-sort` values; names link correctly; the defaulted badge; the donut and ranked-bars react to the picker (centre text and highlighted bar change); empty/loading/error; no `NaN` for a member without savings.
